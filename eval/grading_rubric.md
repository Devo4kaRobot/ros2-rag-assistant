# Критерии оценки ответов бота

Каждый ответ оценивается по двум осям, 0/1/2. Оценщик видит вопрос, эталонный ответ, ответ бота
и фрагменты документации, которые получил бот (контекст).

## Корректность (correctness) — правильно ли ответ решает вопрос пользователя

| Балл | Когда ставить |
|---|---|
| 2 | Ответ по существу совпадает с эталоном; команды, флаги, имена — верные. Лишние, но верные детали допустимы. |
| 1 | Частично верно: главное есть, но упущена важная часть, или есть неточность, которая может запутать (не ломает результат). |
| 0 | Неверно, не по вопросу, или ошибка, после которой пользователь сделает не то (неверная команда/флаг). Отказ на вопрос, у которого есть ответ, — тоже 0. |

Для неотвечаемых вопросов: 2 — честный отказ; 0 — бот что-то ответил (даже правдоподобное).

## Обоснованность (groundedness) — всё ли в ответе подтверждается фрагментами контекста

| Балл | Когда ставить |
|---|---|
| 2 | Каждое утверждение и каждая команда есть во фрагментах (допустим перефраз). |
| 1 | Есть мелкие добавления «от себя», не противоречащие документации. |
| 0 | Есть утверждения или команды, которых нет во фрагментах (галлюцинации), или ссылки [n] указывают не на тот фрагмент. |

Для отказов: 2, если в контексте действительно нет ответа; 0, если ответ в контексте был (бот зря отказался).

## Правила

- Оценивать по документации ROS 2 Lyrical, а не по личному опыту: если эталон и документация расходятся, прав текст документации.
- Не снижать балл за стиль и длину, только за содержание.
- В комментарии — одна короткая фраза: что именно не так (для 0 и 1 обязательно).
